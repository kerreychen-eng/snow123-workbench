# 性质与边界

本文件是根据已证实的历史流程整理的可移植说明，不是此前已存在于技能目录中的原版技能拷贝。导出本包不等于授权执行、恢复例行或扩大权限。

仅在用户明确委托本轮顶帖或搜帖时运行。只在用户授权范围内的群和帖子操作。未加入的群只记录、不互动，不自行申请加群或扩大加群权限。不自动发评论、私信、投稿，不创建或恢复例行。点赞也必须有明确授权。其他机器人的停推窗口不是本流程的通用规则；只有本任务的用户明确给出时限或暂停时才遵守。

遇账户警告、checkpoint、安全检查或不安全浏览器提示，立即停止；不绕过，不换账户、浏览器或入口重试，不承诺有特定自动化工具可用。

# 输入预检

1. 读取本批原文与结构化清单，只以实际来源为准。需要的字段包括：折扣码、ASIN、商品名称或链接、价格或折扣条件、码的生效与截止时间。缺字段就标明，不编造。
2. 按 ASIN + 规范化折扣码，核对本任务已有的 Facebook 搜帖/顶帖历史并去重。其他站点的投稿或扫描记录不能当作 Facebook 已搜历史。历史覆盖不全时写明范围。
3. 分开统计有效候选、过期、无码、批内重复、时区不明。时区不明不猜测。组合券、变体和价格区间保留原文。过期只按原文里明确的时区判定。
4. 输出本轮队列和暂扣清单，不覆盖原始输入文件。

# 搜帖

使用当前环境里实际可用的浏览器或页面操作能力。把下面步骤映射到这些能力，不要依赖某一家工具的专有名称。若没有可用的页面操作能力，停止并报告，不要改用未授权方式访问。

1. 先做精确码搜索：打开 Facebook 帖子搜索，查询词为完整折扣码本身。可用入口形态为 `https://www.facebook.com/search/posts/?q=` 加上经过 URL 编码的码。不要用模糊词冒充精确码命中。
2. 默认将当前排序的结果滚到底，直到确认没有更多结果或页面不再加载；并尝试切换到「最新 / Latest / Newest」再同样滚到底。若用户为本轮指定只看前 N 条，则按该上限执行并记录实际条数。历史 SOP 曾写「只看前 10 帖」，这是可配置上限，不是未声明时的默认截断。
3. 记录真实覆盖：排序方式、是否滚到底、是否尝试最新、实际查看条数、加载失败或结果为空。能拿到准确原帖 permalink 就保存，不要用模糊搜索页代替原帖 URL。
4. 每条候选必须核对：帖文或可见评论是否出现当前要推的码或所搜的旧码、商品是否对得上、ASIN 是否在可见内容或可靠链接中出现。只有码命中但商品或 ASIN 对不上的，单独标注，不当作已核对匹配。ASIN 未在可见内容中出现时标「ASIN 未核实」，不要用短链或近似标题代替。

# 计数与阈值

点赞（Like）和反应总数（所有表情合计）必须分开记录。可见数字若是「赞 / Like」以外的合计或未打开明细，不得记为 Like 数，应标「未核实 Like」。评论数单独记录。不要用摘要、缓存或未展开内容里的数字充当已核实计数。

阈值必须参数化，至少包括：Like 阈值、评论阈值、组合规则（历史均为「任一达到即考虑」，不要改成必须同时达到，除非用户本轮另指定）。历史上出现过两套口径，未配置时不要自动判达标，只记录原始计数并标「阈值未配置」：

- 历史操作口径：Like > 5，或评论 > 3
- SOP 口径（2026-11-11 确认）：点赞和评论分开算，各自以 5 为线，即 Like > 5 或评论 > 5

即使用户配置了阈值，也只用于筛选「可提交预览的候选」，不构成已经批准点赞或评论。

# 互动授权

1. 评论原文必须逐条交给用户预览，获得对该条的明确批准后才能提交。默认评论内容是现在要推广的折扣码，不要扩写成购买体验、使用感受或其他未提供的事实。用户改写后以批准稿为准。
2. 点赞同样要有授权：可以是本轮对已达标且已核对帖子的书面授权，也可以逐条批准。没有授权就不点。
3. 需要加入群组才能看到完整内容或评论时：不申请加入，关闭入群提示，记录群名称、链接、身份/成员状态和原因。
4. 不在未授权的群、主页或帖子上操作，不发私信，不把本流程用于社区型 Deal 站的水军顶帖。

# 记录与交付

为每条保存至少：code、expected_asin、product、search_url、retrieved_at（按用户当前时区汇报并标明时区）、coverage（排序、是否滚到底、是否尝试最新、查看条数）、post_url、group_or_page、membership_or_identity_status、visible_like_count、reaction_total_if_shown、like_count_verified、comment_count、match_check（码/商品/ASIN）、threshold_rule_used、qualifying_status、proposed_comment、approval_status、action_status。

行动状态必须区分：待预览、已批准未提交、已提交、待审核、已发布可见。四者不可混用。未执行的动作不要写成已完成。

先核验保存文件存在且统计与结果相符，再报告：已查码数、精确命中数、核对情况、覆盖范围、阈值是否已配置、待预览评论条数，以及 checkpoint 或其他阻塞。本包不能当作下一次自动执行的许可。
